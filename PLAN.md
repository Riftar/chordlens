# PLAN — chordlens

## Problem

You hear a song and want to know what chords it plays — without uploading
it anywhere, without a cloud service, without a bundled ML model. Chord
detection is a solved classical-DSP problem (chromagram + template
matching) that needs no network and no training data, yet almost every
public tool for it is a web SaaS that ships your audio to someone else's
server. chordlens answers "what chords are in this recording?" entirely
on your machine, in pure Python stdlib plus a dependency-free web client.

## Goals (ceiling)

- Detect chords in real songs: full quality labels (maj/min/7/maj7/
  min7/dim/sus4) on clean recordings; stable chord *roots* even in dense
  mixes where quality labels degrade (drums, bass drones, gain wobble).
- Two front doors on one core: a CLI (`python3 -m chordlens song.wav`)
  and a local web UI (drop a WAV, run the demo loop, see a clickable
  chord timeline + a chromagram heatmap synced to playback).
- Boundary detection: report *when* the chord changes, not just what it
  is — segments with start/end times.
- Everything offline: analysis never leaves localhost; uploads are
  parsed from a tempfile and deleted; the client carries no CDN
  dependency (fonts degrade gracefully to the local mono stack).

## Checkpoints

1. **Core + CLI (shipped).** Pure-stdlib FFT → chroma → harmonic chord
   templates; WAV in, chord timeline out. Deterministic fixtures with
   ground truth (clean/messy/silence) generated by script; unit tests
   gate on detection rates, not eyeballs.
2. **Real-audio robustness (shipped, v0.1.1 quality).** Harmonic templates
   that expect overtone energy (a triad's 3rd partial of the major third
   *is* the major 7th — templates that don't know this read every major
   triad as maj7), NO spectral whitening (measured on real guitar
   recordings: log-compression lifts overtones to parity with fundamentals
   and every triad reads as a 7th chord — raw magnitude keeps fundamentals
   dominant), silence gating, chroma floor above sub-bass drones, temporal
   median smoothing. Messy-fixture ceiling is measured and gated, not
   hidden: interior-frame root accuracy ≥ 0.55 with drums + drone +
   wobble, exact ≥ 0.75 on clean. Real-song check (2026-11-06, four
   YouTube backing tracks): a known Am-F-C-G loop returns exactly those
   four triads as the top four time-weighted labels; an E-major ballad
   returns an E/A/B/C#m palette.
3. **Web UI (shipped).** stdlib http.server serving a single-file client:
   dropzone (all states), /api/analyze POST (32 MB cap, tempfile,
   deleted), chord timeline with click-to-seek, chromagram canvas,
   synced playback, demo loop from /fixtures/.

Ceiling beyond v0.1 (future work, not promised): quality-label accuracy
on dense mixes; boundary frames are straddled by the 0.74 s FFT window
(a multi-resolution front end would sharpen them); live-mic mode.

## Non-goals

- No ML, no model weights, no vendored binaries. Classical DSP only.
- No key detection, no transcription to notes, no beat tracking.
- No MP3/OGG decoding in Python — convert first (`ffmpeg -i in.mp3
  out.wav`); the browser's `<audio>` element plays the WAV locally.

## Rollback

Single-commit repo; `gh repo delete Riftar/chordlens` or local
`rm -rf chordlens` returns the world to its prior state. The server is
localhost-only and holds no state; nothing to migrate or unwind.

## Offline guarantee

Dev and test run without network: `python3 -m unittest discover -s tests`
loops back to 127.0.0.1 only. The client's only external reference is an
optional Google-Fonts stylesheet for Geist Mono — the page is fully
styled and functional without it (offline by design, prettier online).
